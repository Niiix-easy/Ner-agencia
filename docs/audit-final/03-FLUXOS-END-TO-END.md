# 03 — Auditoria de Fluxos End-to-End — NER AGENCY OS

Todos os fluxos abaixo foram rastreados no código-fonte e validados por testes HTTP automatizados (`tests/ner-os.test.ts`, `tests/ner-audit-e2e.test.ts`, `tests/ner-ai-gateway.test.ts`, `tests/ner-ai-cost-intelligence.test.ts`).

| Fluxo | Passos Verificados | Resultado Real & Correções Aplicadas | Status |
|---|---|---|---|
| **Fluxo A — Comercial CRM** | Criar Lead (`POST /api/leads`) → disparar workflow `lead.created` → Converter Lead (`POST /api/leads/:id/convert`) → Criar Cliente + Oportunidade → Mover Kanban (`PATCH /api/opportunities/:id`) → Emitir Proposta → Aceitar (`PATCH /api/proposals/:id/accept`) → Gerar Contrato + Recebível | **Corrigido na auditoria**: `proposals/:id/accept` agora herda `serviceType` e `recurrence` do `CommercialPlan` via `planCode` e cria `Receivable` pendente (`mediaBudget: 0`). | **FUNCIONANDO** |
| **Fluxo B — Digital Studio → Projetos** | Editar preços Setup/Recorrência separados (`PATCH /api/plans/:id`) → Contratar plano (`POST /api/digital-studio/contract`) → Criar Contrato + Recebível + Projeto + Entregáveis por template + Tarefas → Concluir tarefas → Progresso 100% + Time Tracking | **Corrigido na auditoria**: IDs agora possuem sufixo randômico criptográfico, eliminando colisões em rajadas simultâneas (validado com 5 contratações paralelas no mesmo ms). | **FUNCIONANDO** |
| **Fluxo C — Aprovações** | Solicitar aprovação (`POST /api/approvals`) → Tentar aprovar com `expectedVersion` antiga → Rejeição `409` → Aprovar com versão atual (`v1.0`) | `clientId` e `deliverableId` validados no tenant; histórico imutável preservado. | **FUNCIONANDO** |
| **Fluxo D — Financeiro e Comissões** | Verificar `agencyRevenue` vs `mediaBudgetSeparated` → Baixar Recebível (`POST /api/finance/receivables/:id/payments`) → Desbloquear comissão vinculada → Registrar Conta a Pagar | Separação contábil validada (`mediaBudget` nunca soma em receita da agência). Comissões vinculadas transitam automaticamente para `Liberada`. | **FUNCIONANDO** |
| **Fluxo E — Web & Tracking** | Criar LP (`POST /api/web/pages`) → Publicar → Submeter lead público (`POST /api/web/pages/:id/submit-lead`) → Criar Lead + TrackingEvent → Reenviar mesmo `eventId` → Deduplicação | Página publicada aceita lead público e alimenta CRM + Tracking com deduplicação determinística por `eventId`. | **FUNCIONANDO** |
| **Fluxo F — Billing & Webhooks** | `POST /api/billing/checkout` mantém assinatura `incomplete` → Webhook sem HMAC válido retorna `401` → Webhook assinado ativa plano → Reenvio do mesmo `eventId` retorna `duplicate: true` | **Corrigido na auditoria**: Em `NODE_ENV=production` sem `STRIPE_WEBHOOK_SECRET`, retorna `503` (fail-closed, sem fallback sandbox). Checkout API live pendente de `STRIPE_SECRET_KEY`. | **FUNCIONANDO PARCIALMENTE** |
| **Fluxo G — IA Departamental & Custos** | Configurar provedor AES-256-GCM → Executar `POST /api/ai/department/execute` → Registrar `AiUsageLog` em USD/BRL → Consultar Dashboard `/api/ai/dashboard` e exportar CSV/XLSX/PDF | **Corrigido na auditoria**: `POST /api/ai/department/execute` agora exige permissão `ai.use`/`ai.client_assist`, valida org/client/project e rejeita com `403` usuário `Cliente` tentando spoofar outro `clientId`. | **FUNCIONANDO** *(com provedores fake nos testes; real aguarda API Keys)* |
| **Fluxo H — Governança LGPD** | Exportar portabilidade (`GET /api/lgpd/clients/:id/export`) → Anonimizar titular (`POST /api/lgpd/clients/:id/anonymize`) | **Implementado na auditoria (API + UI em `CoreViews.tsx`)**: Exporta pacote JSON, anonimiza PII em Client/Lead/Receivable, desativa usuários ligados, revoga sessões ativas e remove memórias de IA preservando IDs fiscais. | **FUNCIONANDO** |
